## 1. 仮想世界の作り方

### 1-1. オブジェクトを生み出す手順

chapter07でまなんだように、オブジェクト指向の考え方に沿って開発されたプログラムは、  
動作時に「現実世界をマネたそれぞれのオブジェクトが、互いに連携して動く仮想世界」を形成する。  
そのように考えると、開発者の仕事は以下の2つであると考えられる。

1. 各オブジェクトが負うべき責務を考え、「属性」「操作」の種類と内容を定義する
2. 各オブジェクトを仮想世界に生み出し、動かす。

しかし、Javaにおいては、仮想世界の中で動くオブジェクトそのものを開発者が直接定義することはできない。  
その代わりに開発者は、オブジェクトが生み出す際に用いられる、「オブジェクトの設計図」であるクラスを定義できる。  
上記を訂正すると、

1. クラスを定義する
2. そのクラスに基づいてオブジェクトを生成する

この2つが正しい。

開発時はクラスを定義し、それをコンパイルすることで仮想世界を生み出す。  
そして実行時にクラスファイルからオブジェクトを生み出すという流れである。

## 1-2. クラスとオブジェクトが別である理由

なぜJavaでは「オブジェクト同士が連携する仮想世界」を作るために、  
わざわざ「クラスを定義して、そのクラスからオブジェクトを生成する」という複雑な手順を踏まなければならないのだろうか。

ここでオブジェクトを大量に作る必要がある状況を想像してみよう。  
例えば銀行システムで、全ての口座情報を対象にした複雑な統計を行うプログラムが動くとき、  
その仮想世界には「口座」オブジェクトはいくつ必要だろうか？  
口座が1,000あるなら1,000個のオブジェクトを生み出す必要があるかもしれない。  
1,000個の口座オブジェクトそれぞれに対して、「属性として残高・名義人・開設日があって・・・」という定義を繰り返すとしたら、  
それを作る開発者の作業は膨大なものになる。

そこでクラスの登場である。  
「属性として、残高・名義人・開設日があって・・・」を定義した「口座クラス」を一つだけ作っておけば、  
このクラスから100個でも1,000個でも必要な数だけオブジェクトを生み出すことができる。  
例えば、振り込みを受け付ける「Uketsukeクラス」を1つ準備しておけば、  
複数の受付係を生み出して、「並行して振り込み依頼を受け付ける」プログラムを作ることもできる。

ここで意識することは、**クラスとオブジェクトは全く違うものである**という点である。  
プログラムの動作時に仮想世界の中で活躍するのは「オブジェクト」だけであって、  
その金型であるクラスが仮想世界で活動することはない。  
「受付係の金型」が挨拶したり振り込みを受け付けたりはしない。

## 1-3. オブジェクトという用語のあいまいさ

実際の開発現場における技術的な会話や文章中で単に「オブジェクト」という表現が用いられる場合、  
金型か、その金型から生まれた実体かを厳密に区別しないことがある。  
つまり、**「オブジェクト」は、ときどきクラスのことを指して使われることもある、非常にあいまいな用語**である。  

もし「金型ではなく、その型から生み出された仮想世界で活動する実体」を厳密に示したい場合はインスタンスと呼ぶ。  
また、クラスからインスタンスを生成する行為をインスタンス化と表現する。  

まとめると、インスタンスとクラスの関係は、  
仮想世界で活動するのはインスタンスであり、  
そのインスタンンスを生み出す金型がクラスである。

## 1-4. プログラムに登場する2種類のクラス

ここから「勇者とお化けキノコの戦い」のプログラム化を始める。
それにあたって、まず必要だと思いつくのは、  
勇者クラスとお化けキノコクラスである。  
これらは、「現実世界に登場する金型」なので、  
ここでは「登場人物クラス」とする。

しかしこれら「登場人物クラス」だけではプログラムは動かない。  
勇者やお化けキノコは誰かから指示（操作の呼び出し）をされて責任を果たすために動くので、  
この2つだけインスタンス化しても「指示待ち」状態になってしまう。

そこで「仮想世界の神様」たる開発者が、  
この2人の登場人物にどのように動くかを指示していく必要がある。  
開発者の指示である「天の声」は具体的にmainメソッドとして記述していく。

なお、ただ単にmainメソッドを記述したいだけだとしても、  
メソッドはクラスの中に作るというJavaのルールを守る必要がある。  
よって、Mainなど適当な名前でクラスを1つ作り、  
その中にmainメソッドを作成する。

chapter08/src/Main.java
```
public class Main {
    public static void main(String[] args) {
        // (以下の内容をJavaで記述していく)
        // 勇者よ、この仮想世界に生まれよ！
        // お化けキノコよ、この仮想世界に生まれよ！
        // 勇者よ、戦え！
        // お化けキノコよ、逃げろ！
    }
}
```

そして、Mainクラスのmainメソッドを起動するコマンドを入力すると、  
勇者やお化けキノコが動き出す。

```
java -cp ../bin Main 
```

このMainクラスだけは、現実世界を模したものではなく、  
インスタンス化して利用するものではない。  
あくまでも仮想世界の神様としてそれぞれの登場人物を生み出し、  
それらに対して指示を出す役割を担っている。  
(以降このクラスを「神様クラス」と表現する)  
プログラムを作る場合には「登場人物クラス」と「神様クラス」の2種類を作る必要がある。

まとめると、Javaプログラムの組成に必要なクラスたちとは、  
1. mainメソッドを含む「神様クラス」
2. 現実世界の登場人物を模した、複数の「登場人物クラス」

今回の「勇者とお化けキノコの戦い」では、  
最低でも3つのクラスの開発が必要になる。

1. Mainクラス(神様クラス)
2. Heroクラス(登場人物クラス)
3. Matangoクラス(登場人物クラス)

オブジェクト指向の概念に照らし合わせて混乱を招かないためにも、  
このMainメソッドは必要である。
