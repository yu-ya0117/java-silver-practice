## 1. 仮想世界の作り方

### 1-1. オブジェクトを生み出す手順

chapter07でまなんだように、オブジェクト指向の考え方に沿って開発されたプログラムは、  
動作時に「現実世界をマネたそれぞれのオブジェクトが、互いに連携して動く仮想世界」を形成する。  
そのように考えると、開発者の仕事は以下の2つであると考えられる。

1. 各オブジェクトが負うべき責務を考え、「属性」「操作」の種類と内容を定義する
2. 各オブジェクトを仮想世界に生み出し、動かす。

しかし、Javaにおいては、仮想世界の中で動くオブジェクトそのものを開発者が直接定義することはできない。  
その代わりに開発者は、オブジェクトが生み出す際に用いられる、「オブジェクトの設計図」であるクラスを定義できる。  
上記を訂正すると、

1. クラスを定義する
2. そのクラスに基づいてオブジェクトを生成する

この2つが正しい。

開発時はクラスを定義し、それをコンパイルすることで仮想世界を生み出す。  
そして実行時にクラスファイルからオブジェクトを生み出すという流れである。

## 1-2. クラスとオブジェクトが別である理由

なぜJavaでは「オブジェクト同士が連携する仮想世界」を作るために、  
わざわざ「クラスを定義して、そのクラスからオブジェクトを生成する」という複雑な手順を踏まなければならないのだろうか。

ここでオブジェクトを大量に作る必要がある状況を想像してみよう。  
例えば銀行システムで、全ての口座情報を対象にした複雑な統計を行うプログラムが動くとき、  
その仮想世界には「口座」オブジェクトはいくつ必要だろうか？  
口座が1,000あるなら1,000個のオブジェクトを生み出す必要があるかもしれない。  
1,000個の口座オブジェクトそれぞれに対して、「属性として残高・名義人・開設日があって・・・」という定義を繰り返すとしたら、  
それを作る開発者の作業は膨大なものになる。

そこでクラスの登場である。  
「属性として、残高・名義人・開設日があって・・・」を定義した「口座クラス」を一つだけ作っておけば、  
このクラスから100個でも1,000個でも必要な数だけオブジェクトを生み出すことができる。  
例えば、振り込みを受け付ける「Uketsukeクラス」を1つ準備しておけば、  
複数の受付係を生み出して、「並行して振り込み依頼を受け付ける」プログラムを作ることもできる。

ここで意識することは、**クラスとオブジェクトは全く違うものである**という点である。  
プログラムの動作時に仮想世界の中で活躍するのは「オブジェクト」だけであって、  
その金型であるクラスが仮想世界で活動することはない。  
「受付係の金型」が挨拶したり振り込みを受け付けたりはしない。

## 1-3. オブジェクトという用語のあいまいさ

実際の開発現場における技術的な会話や文章中で単に「オブジェクト」という表現が用いられる場合、  
金型か、その金型から生まれた実体かを厳密に区別しないことがある。  
つまり、**「オブジェクト」は、ときどきクラスのことを指して使われることもある、非常にあいまいな用語**である。  

もし「金型ではなく、その型から生み出された仮想世界で活動する実体」を厳密に示したい場合はインスタンスと呼ぶ。  
また、クラスからインスタンスを生成する行為をインスタンス化と表現する。  

まとめると、インスタンスとクラスの関係は、  
仮想世界で活動するのはインスタンスであり、  
そのインスタンンスを生み出す金型がクラスである。

## 1-4. プログラムに登場する2種類のクラス

ここから「勇者とお化けキノコの戦い」のプログラム化を始める。
それにあたって、まず必要だと思いつくのは、  
勇者クラスとお化けキノコクラスである。  
これらは、「現実世界に登場する金型」なので、  
ここでは「登場人物クラス」とする。

しかしこれら「登場人物クラス」だけではプログラムは動かない。  
勇者やお化けキノコは誰かから指示（操作の呼び出し）をされて責任を果たすために動くので、  
この2つだけインスタンス化しても「指示待ち」状態になってしまう。

そこで「仮想世界の神様」たる開発者が、  
この2人の登場人物にどのように動くかを指示していく必要がある。  
開発者の指示である「天の声」は具体的にmainメソッドとして記述していく。

なお、ただ単にmainメソッドを記述したいだけだとしても、  
メソッドはクラスの中に作るというJavaのルールを守る必要がある。  
よって、Mainなど適当な名前でクラスを1つ作り、  
その中にmainメソッドを作成する。

chapter08/src/Main.java
```
public class Main {
    public static void main(String[] args) {
        // (以下の内容をJavaで記述していく)
        // 勇者よ、この仮想世界に生まれよ！
        // お化けキノコよ、この仮想世界に生まれよ！
        // 勇者よ、戦え！
        // お化けキノコよ、逃げろ！
    }
}
```

そして、Mainクラスのmainメソッドを起動するコマンドを入力すると、  
勇者やお化けキノコが動き出す。

```
java -cp ../bin Main 
```

このMainクラスだけは、現実世界を模したものではなく、  
インスタンス化して利用するものではない。  
あくまでも仮想世界の神様としてそれぞれの登場人物を生み出し、  
それらに対して指示を出す役割を担っている。  
(以降このクラスを「神様クラス」と表現する)  
プログラムを作る場合には「登場人物クラス」と「神様クラス」の2種類を作る必要がある。

まとめると、Javaプログラムの組成に必要なクラスたちとは、  
1. mainメソッドを含む「神様クラス」
2. 現実世界の登場人物を模した、複数の「登場人物クラス」

今回の「勇者とお化けキノコの戦い」では、  
最低でも3つのクラスの開発が必要になる。

1. Mainクラス(神様クラス)
2. Heroクラス(登場人物クラス)
3. Matangoクラス(登場人物クラス)

オブジェクト指向の概念に照らし合わせて混乱を招かないためにも、  
このMainメソッドは必要である。

## 2. クラスの定義方法

### 2-1. 登場人物クラスの作り方

ここからはHeroやMatangoクラスを作るために、  
クラスの定義方法を学んでいく。

クラスには「どのような属性を持っているか」を記述していく。  
現時点で自分たちが思い描く「勇者クラスが持つべき属性や操作」を図にまとめる。

[![Image from Gyazo](https://i.gyazo.com/0529f80eb8cf82bbca8019f4b9fddf5b.png)](https://gyazo.com/0529f80eb8cf82bbca8019f4b9fddf5b)

この図のように、あるクラスの「クラス名」「属性」「操作」を上から一覧として並べる書き方は、  
クラス図と呼ばれる設計図ルールに準じたものである。  
クラス図は、世界共通の設計図であるUML(Unified Modeling Language)で定められている図の一つである。  

この設計に基づいて記述したJavaプログラムが以下のコードである。

```
public class Hero {
    String name;
    int hp;

    public void attack(){};

    public void sleep(){};

    public void sit(int sec){};

    public void slip(){};

    public void run(){};
}
```

### 2-2. クラスの宣言方法

クラスの宣言にはclassキーワードを使用する。  
以下は中身のない空のHeroクラスを宣言している。

```
public class Hero {
}
```

### 2-3. 属性の宣言方法

2-1で示した図によると、  
勇者クラスが持つ属性は名前とHPである。  
これらの属性について、  
プログラムで使用する変数名と型を考える。  
名前は文字列なのでString型、  
HPは数値なのでint型とする。

- 【名前】name(String型)
- 【HP】hp(int型)

これらの変数をクラスのブロック内に宣言したものが以下になる。

```
public class Hero {
    String name;  // 名前の宣言
    int hp;       // HPのの宣言
}
```

上記のように、クラスブロック内に宣言された変数を、  
Javaでは特にフィールドという。  
これで、nameとhpという2つのフィールドの宣言が完了した。

フィールドの宣言について、  
属性を宣言するにはクラスブロックの中に変数宣言を記述する。

## 2-4. 属性の初期値設定と定数フィールド

フィールド宣言と同時に値の代入も記述すると、  
そのフィールドの初期値設定ができる。

chapter08/src/Matango.java
```
public class Matango{
    int hp;
    int level = 10;
}
```

フィールド宣言の先頭にfinalをつけると、  
値を書き換えられない定数フィールドになる。  
定数フィールドは一目でわかるように大文字で記載することが推奨されている。

```
public class Matango{
    int hp;
    final int LEVEL = 10;
}
```

## 2-5. 操作の宣言方法

次に、Heroクラスの操作を「記述」していく。  
「操作」を定義するには以下が必要になる。

- 操作の名前
- 操作する時に必要な情報一覧
- 操作の結果として指示元に返す情報
- 処理内容

以上の4つを考える必要がある。

例えば「眠る」という操作の具体的な要素として、  
以下のように考えたとする。

- 【名前】sleep
- 【必要情報】なし
- 【結果】なし
- 【処理内容】HPが100に回復する

これらをHeroクラスのクラスブロックの中に記載すると以下のようになる。

```
public class Hero {
    String name;
    int hp;

    public void sleep(){
        this.hp = 100;
        System.out.println(this.name + "は、眠って回復した！");
    };
}
```

ここでthisというキーワードが出てくる。  
thisは特別に準備された変数で、  
「自分自身のインスタンス」を意味している。  
また、.(ドット)には、日本語でいう「の」と同じ意味があるので、

```
this.hp = 100;
```
これは**自分自身のインスタンスのhpフィールドに100を代入する**という意味になる。

以上でHeroクラスにsleepメソッドを宣言することができた。

※sleepメソッドにstaticをつけない理由はchapter14で詳しく取り扱う。

## 2-6. クラス名とメンバ名のルール

ここで紹介したフィールドとメソッドは、メンバと総称される。  
そしてクラス名やメンバ名は、基本的に識別子のルールに沿っていれば自由に決めることができるが、  
実際には以下のような慣例に従って名前をつけるのが望ましいとされる。  

| 対象     | 品詞 | 大文字/小文字の用法 | 例                    |
|--------|----|----------|----------------------|
| クラス名   | 名詞 | 単語の頭が大文字 | Hero、MonsterInfo     |
| フィールド名 | 名詞 | 最初以外の単語の頭が大文字 | level、itemList       |
| メソッド名  | 動詞 | 最初以外の単語の頭が大文字 | attack、findWeakPoint |

## 2-7. クラス定義のまとめ

ここまで、Heroクラスを題材にクラスの定義方法を学んできた。  
クラスを定義するには、「属性」と「操作」の一覧を図にまとめる。  
そして、それぞれ「フィールド」と「メソッド」としてJavaのコードに書き換えて記述していく。

この考え方に沿って、Heroクラスに「座る」「転ぶ」「逃げる」メソッドを追加したのが以下のコードである。

chapter08/code08-01/src/Hero.java
```
public class Hero {
    String name;
    int hp;

    public void sleep(){
        this.hp = 100;
        System.out.println(this.name + "は、眠って回復した！");
    };

    public void sit(int sec){
        this.hp += sec;
        System.out.println(this.name + "は、" + sec + "秒座った！");
        System.out.println("HPが" + sec + "ポイント回復した");
    };

    public void slip(){
        this.hp -= 5;
        System.out.println(this.name + "は、転んだ！");
        System.out.println("5のダメージ！");
    };

    public void run(){
        System.out.println(this.name + "は、逃げ出した！");
        System.out.println("GAMEOVER");
        System.out.println("最終HPは、" + this.hp + "でした");
    };
}
```

ここで注意すべきことはthisを省略しないこと。  
同じクラス内のフィールドにアクセスする場合、  
`this.`を省略しても動作はする。  
たとえば、`this.hp = 100;`と`hp = 100;`は同じ動作である。  
しかしローカル変数や引数にも同じhpという名前の変数が存在する場合、  
そちらが優先されてしまうなど予想外の動作をする可能性がある。  
フィールドを指示するときには明示的に`this.`をつけること。

## 3. クラス定義による効果

### 3-1. クラス定義によって可能になる2つのこと

前節で、Heroクラスを定義することができた。  
Javaでは、このようにあるクラスを定義すると、  
2つのことが可能になる。

1. そのクラスに基づいて、インスタンスを生成することができるようになる
2. そのクラスから生まれたインスタンスを代入する変数の型が利用できるようになる

例えば、Heroクラスを定義すると、Hero型の変数が利用できるようになる。  
このように、クラス定義によって利用可能になる型のことをクラス型という。

### 3-2. クラス変数とは

Javaで扱う全ての変数は必ず何かしらの型を持っている。  
今まで利用してきた「整数を入れるためのint型」や、  
「文字列を入れるためのString型」は、Java標準で準備しており、  
いつでも使える型であった。

それに加え、例えばHeroクラスを定義すると、  
「Heroクラスから仮想世界に生み出されたインスタンスを代入できるHero型」が使えるようになる。  
つまり、クラスを定義すれば、Javaで利用可能な型の種類はどんどん増えていく。

- 最初に使える型：int型、double型、String型、int[]型 etc...  
- クラスHeroを定義したら：Hero型  
- クラスSwordを定義したら：Sword型

クラス型を準備する方法は、int型やString型と一緒である。

以下はHero型の変数の宣言方法である(宣言のみ抜粋)
```
Hero h;
```

このHero型変数hには、まだ勇者インスタンスは入っていませんが、  
今後「仮想正解に生み出した勇者のインスタンス」を代入していく。  
インスタンスは通常、クラス型変数に入れて利用する。

### 3-3. クラス型変数が必要な理由

なぜHero型の変数にインスタンスを代入する必要があるのか？

[![Image from Gyazo](https://i.gyazo.com/9bf483139cdd44d9693b6aee8620a947.png)](https://gyazo.com/9bf483139cdd44d9693b6aee8620a947)

※厳密にはrecoverという操作は実装していない

定義済みのクラスHeroから2つの勇者インスタンスを生み出した状態だが、  
どちらも同じ「ミナト」という名前で、HPも同じく100である。  
上記の勇者インスタンス②の方の勇者「ミナト」に「眠れ」という指示を送るには、  
どのようにプログラムを記述すればいいのか？  

図では「勇者インスタンス①のミナト」「勇者インスタンス②のミナト」と表現できるが、  
仮想世界では2人の勇者を識別する術がないため、  
指示を送ろうにも相手を特定できない。  

しかし、もしこの勇者2人が、それぞれ変数h1、h2に入っているなら問題は解決する。  
**h2の勇者に眠れという指示を送る**とプログラムを書けばよい。

クラス型変数を用いる理由をまとめると、  
仮想世界に複数存在しうる同名のインスタンスから、  
特定の1つのインスタンスをプログラムとして識別するためである。

## 4. インスタンスの利用方法

### 4-1. 「神様クラス」の作り方

Heroクラスだけではプログラムは動かない。  
勇者に指示を出す「天の声」の実装をまだ行っていない。  
ここでは「神様クラス」であるMainクラスを作成していく。

```
public class Main {
    public static void main(String[] args) {
        // ここに勇者への指示を書いていく
    }
}
```

mainメソッドに以下の内容を記述していく。

1. 仮想世界に勇者を生み出す。
2. 生み出された勇者に、最初の名前とHPを設定する。
3. 勇者に「5秒座れ」「転べ」「25秒座れ」「逃げろ」と指示を出す。

### 4-2. インスタンスの生成方法

仮想世界に勇者を生み出すために、  
インスタンスの生成方法を学ぶ。

通常Heroクラスという金型から実体のあるインスタンスを生成するには以下のように記述する。

- インスタンスの生成
```
クラス名 変数名 = new クラス名();
```

この文法に従って作成したMainクラスは以下のようになる。

```
public class Main {
    public static void main(String[] args) {
        Hero h = new Hero();  // Heroクラスからインスタンスを生成し、変数hに代入する
    }
}
```

ここで実際にインスタンスを生成しているのは、  
右辺のnew Hero()の部分である。  
その後、生成したインスタンスを=によって、  
Hero型の変数hに代入している。
（※この過程の詳細は後ほど説明する）

上記では1行で記述しているが、  
```
Hero h;
h = new Hero();
```
と2行に分けて記述しても同じ意味になる。

### 4-3. インスタンスフィールドの利用

生み出されたばかりの勇者hには、  
まだ名前もHPもないので、  
それぞれのフィールドに値を代入する。  
勇者hフィールドに値を代入するには、 
次の構文を使用する。

- フィールドへの値の代入
```
変数名.フィールド名 = 値;
```

なお、フィールド値を取得するには、単に`変数名.フィールド名`と記述する。

ここまでの学習内容を用いてmainメソッドを改良したものが以下になる。

```
public class Main {
    public static void main(String[] args) {
        // 1. 勇者を生成
        Hero h = new Hero();

        // 2. フィールドに初期値をセット
        h.name = "ミナト";
        h.hp = 100;
        System.out.println("勇者" + h.name + "を生み出しました！");
    }
}
```

### 4-4. インスタンスのメソッド呼び出し

いよいよ冒険の始まりとなる。  
様々な指示を勇者に送ってみよう。  
指示は「メソッド呼び出し」で実現する。

chapter08/code08-01/src/Main.java
```
public class Main {
    public static void main(String[] args) {
        // 1. 勇者を生成
        Hero h = new Hero();

        // 2. フィールドに初期値をセット
        h.name = "ミナト";
        h.hp = 100;
        System.out.println("勇者" + h.name + "を生み出しました！");

        // 3. 勇者のメソッドを呼び出していく
        h.sit(5);   // 5秒座れ
        h.slip();   //転べ
        h.sit(25);  //25秒座れ
        h.run();    //逃げろ
    }
}
```

コンパイルして実行すると
```
javac -d ../bin Main.java Hero.java
java -cp ../bin Main
勇者ミナトを生み出しました！
ミナトは、5秒座った！
HPが5ポイント回復した
ミナトは、転んだ！
5のダメージ！
ミナトは、25秒座った！
HPが25ポイント回復した
ミナトは、逃げ出した！
GAMEOVER
最終HPは、125でした
```

ここで注目すべきは、このmainメソッドの内容が、  
まるで冒険物語のシナリオのようでわかりやすいという点である。  
手続き型プログラミングだと、  
mainメソッドの中にいくつものHP処理やSystem.out.println()の呼び出しを繰り返す必要があり、  
非常に面倒なのでここでは省略する。

オブジェクト指向プログラミングの場合、  
HPを増やしたり減らしたりする計算や、  
画面に表示するメッセージの指示が一切出てこないことに気づく。

mainメソッドに記述されているのは、  
勇者を登場させて、「座れ」→「転べ」→「座れ」→「逃げろ」という指示だけ。  
にもかかわらず、動作結果として、勇者が行動するたびにHPの増減が処理され、  
画面には10行の表示がなされており、  
最終的なHPが125であることが正しく出力できている。

これは小規模な例ではあるが、  
オブジェクト指向を使うとプログラムが把握しやすくなることが体験できた。

### 4-5. インスタンス利用のまとめ

これまでの学習で、定義済みのHeroクラスから勇者インスタンスを生成し、  
そのフィールドに値を代入したり、  
様々な指示ができるようになった。  

整理すると次のようになる。

- インスタンスの生成には、`new`を使う。
- フィールドを利用する場合は、`変数名.フィールド名`と記述する。
- メソッドを呼び出す場合は、`変数名.メソッド名()`と記述する。

ここまでの学習内容を使って、  
仮想世界に勇者とお化けキノコ2匹を生み出すプログラムを書くと以下のようなものになる。

chapter08/src/Matango.java
```
public class Matango{
    int hp;
    final int LEVEL = 10;
    char suffix;
    public void run(){
        System.out.println("お化けキノコ" + this.suffix + "は逃げ出した！");
    }
}
```

chapter08/src/Main.java
```
public class Main {
    public static void main(String[] args) {
        // 勇者を生成し初期化
        Hero h = new Hero();
        h.name = "ミナト";
        h.hp = 100;

        // お化けキノコAを生成し初期化
        Matango m1 = new Matango();
        m1.hp = 50;

        Matango m2 = new Matango();
        m2.hp = 48;
        m2.suffix = 'B';

        h.slip();   // 勇者は転ぶ
        m1.run();   // お化けキノコAが逃げる
        m2.run();   // お化けキノコBも逃げる
        h.run();    // 勇者も逃げる
    }
}
```

### 4-6. オブジェクト指向は現実世界と繋がっている。

このchapter08で作成したHeroクラスのコードと、  
chapter01〜chapter06までのコードを見比べてみよう。
どちらも`public class クラス名`で宣言されたクラスであり、  
文法的にはどちらも正しいクラスである。  
しかし、両者には「クラスを何のために用いるか」という思想が伴っているか否かに決定的なちがいがある。

非オブジェクト指向のクラスは、何を基準にクラスとするか、  
何を基準にメソッドとするかという明確な思想はなかった。  
強いて挙げるなら「そろそろメソッドが大きくなってきたので分割しよう」、  
あるいは「この機能のメソッドはこのクラスにまとめておこう」などといった、  
開発者の都合や機能の単位に即してクラスやメソッドを作った。

一方、chapter08のHeroクラスなどは、  
「オブジェクト指向」という明確な思想に基づいてクラスやメソッドが作られている。  
つまり、現実世界の登場人物を1つのクラスとして捉え、  
その登場人物の持つ属性をフィールドに、  
そして操作をメソッドとしてコードを書いた。

chapter06までは、「現実世界とは無関係のクラス」のみを取り扱ってきたが、  
chapter08で初めて「現実世界と意味がつながったクラス」に出会うことになった。  
それが「印象が違う」理由である。

オブジェクト指向を意識したプログラム開発とは、  
現実世界の人や物、出来事をクラスに置き換えていく作業にほかならない。  
例えば、自動車組み立て工場のシステムを作るなら、  
「Car」や「Engine」といった部品のクラスを作る。  
あるいは、学生と教員を管理するプログラムならば、  
「Student」や「Teacher」といったクラスを作ることになる。

**現実に似せて作り、現実に似せてうごかしていく**

これがオブジェクト指向の根本的な思想である。

## まとめ

- インスタンスとクラス
  - 仮想世界で活躍するのは「インスタンス」(オブジェクトともいう)。
  - インスタンスを生み出す金型が「クラス」。
  - インスタンスとクラスは全くの別物であり、混同してはならない。
- フィールドとメソッド
  - クラスには、属性としてフィールドを、操作としてメソッドを宣言する。
  - finalがついたフィールドは定数フィールドであり、値が不変である。
  - thisは、「自分のインスタンス」を表すキーワードである。
- クラス型
  - クラスを定義すると、そのクラス型の変数を宣言できるようになる。
  - あるクラス型の変数には、そのクラスのインスタンスを格納する。
- インスタンス化
  - new演算子で、クラスからインスタンスを生み出せる。
  - あるクラス型変数にインスタンスが格納されているとき、`変数名.フィールド名`でフィールドを、`変数名.メソッド名()`でメソッドを利用できる。

## 以下2周目

### 1. オブジェクトを生み出す手順

オブジェクト指向の考え方に沿って開発されたプログラムは、  
動作時に「現実世界を真似したそれぞれのオブジェクトが、互いに連携して動く仮想世界」を形成する。  

ここで開発側がやることは以下の2つ。

1. 「クラス」を定義する。
2. 定義したクラスに基づいて「オブジェクト」を生成する。

Javaでは直接「オブジェクト」を定義できない。  
あくまでも定義するのは「クラス」である。

### 2. クラスとオブジェクトが別々な理由

大量にオブジェクトを生成する状況にある場合のことを想像してみる。

銀行システムで、全ての口座情報に複雑な統計を行うプログラムが動くとき、  
口座が1,000個ある場合は、1,000個のオブジェクトそれぞれに  
「属性として残高や名義人・開設日など・・・」の定義を繰り返すと途方に暮れる。  

そこで1つのクラスをあらかじめ作っておくと、  
この1つのクラスから1,000個でも10,000個でも、  
必要な数だけ簡単にオブジェクトを生成することが可能になる。

注意すべきは、**クラスとオブジェクトはまったく違う**ということ。  
たとえば受付係クラスがあるとする。  
受付係が仮想世界で活躍するのは、  
クラスから生み出されたオブジェクト(実体)だけである。  
クラスそのものは、いわば「金型」に等しい。  
「金型」であるクラスが挨拶したり振り込みの受付をしたりするわけではない。  

### 3. オブジェクトは曖昧な用語

実は「オブジェクト」という用語は曖昧な用語であり、  
開発現場においては上記のような「金型」なのか、  
それとも「実体」なのかを区別しないことがある。  
つまり、「オブジェクト」という言葉は時に「クラス」のことを指して使われることがある。  

もし「金型」ではなく、「金型から生み出された実体」を厳密に指す場合は「インスタンス」という言葉を使う。  
また、クラスから実体を生み出すことをインスタンス化と呼ぶ。

以上から、仮想世界で活躍するのはインスタンスであり、  
そのインスタンスを生み出す金型がクラスであると言える。

### 4. プログラム作成に必要な2種類のクラス

ここから「勇者とお化けキノコの戦い」のプログラムを作成していく。  
そこで、どんなクラスが必要なのかを考える。

まず以上からわかるのは、以下の2つのクラスだろう。

1. 勇者クラス
2. お化けキノコクラス

しかしこの2つのクラスだけではプログラムは動作しない。それはなぜか？  

あくまで上記2つのクラスは「登場人物のクラス」であり、  
誰かから指示(操作の呼び出し)をされて初めて責務を果たすクラスである。
これらのクラスを定義してインスタンス化しても、  
仮想世界の勇者とお化けキノコは指示待ちの状態になってしまう。  

ではどうすれば仮想世界の登場人物は動いてくれるのか？

仮想世界における「神様」である開発者が勇者やお化けキノコに指示を出す必要がある。  
つまり、開発者の指示である「天の声」をmainメソッドとして記述する。  
Javaのルールに則り、Mainなどの適当な名前のクラスを作成し、  
その中にmainメソッドを記述する必要がある。  
ここではこのクラスを「神様のクラス」と呼ぶことにする。

以上からJavaのプログラムを作成するのに必要なのは以下の2種類である。

1. mainメソッドを含む「神様のクラス」
2. 現実世界の登場人物を真似た「登場人物のクラス」

mainメソッドのイメージは以下の通り（一例）
```
public class Main {
    public static void main(String[] args) {
        //  (以下の内容をJavaで記述していく)
        //  勇者よ、この仮想世界に生まれよ！
        //  お化けキノコよ、この仮想世界に生まれよ！
        //  勇者よ、戦え！
        //  お化けキノコよ、逃げろ！
    }
}
```
以降は登場人物のクラスを作成していく。

### 5. クラスの定義方法

#### 5-1. 登場人物のクラスの作り方

ここから勇者(Hero)クラスとお化けキノコ(Matango)クラスを作成していく。  

これら登場人物のクラスには、どのような属性や操作を持っているかを記述する。  
まず、現時点で思いつく勇者クラスが持つべき属性や操作を図にしてみる。  
(※図は1周目で記載済みなのでここでは省略する)

作成した図は、あるクラスの「クラス名」「属性」「操作」を上から一覧として並べて書いている。  
この図をクラス図と呼ぶ。  
クラス図はUML(unified Modeling Language)の略である。  

この設計に基づいて記述したJavaコードが以下のようになる。

```
public class Hero {
    String name;
    int hp;

    public void attack(){};
    public void sleep(){};
    public void sit(int sec){};
    public void slip(){};
    public void run(){};
}
```

#### 5-2. クラスの宣言方法

classキーワードを使って以下のように記述する。  
以下は中身のない空っぽのHeroクラスを宣言している。

```
public class Hero {
}
```

#### 5-3. 属性の宣言方法

勇者は名前とHPの2つの属性を持っている。  
これら属性について、変数名と型を考える。  
すると以下のようになる。  

```
String name;  //  名前：String型
int hp;       //  HP：int型
```

これをHeroクラスのブロック内に宣言したものが以下になる。

```
public class Hero {
    String name;
    int hp;
}
```

このようにクラスブロック内に宣言された変数をフィールドという。  

#### 5-4. 属性の初期値指定と定数フィールド

以下のように記述すると、フィールドの初期値の設定が可能になる。

```
public class Matango{
    int hp;
    int level = 10; // お化けキノコのレベルに初期値10を設定した
}
```
また、フィールドの先頭にfinalをつけると、  
値を変更できない定数フィールドになる。
```
public class Matango{
    int hp;
    final int LEVEL = 10;   // LEVELは10で固定される
}
```

#### 5-5. 操作の宣言方法

次にHeroクラスの操作を記述する。

操作を定義するには、以下の4つが必要になる。

1. 操作の名前(メソッド名)
2. 操作するときに必要な情報の一覧(メソッドの引数)
3. 操作の結果として指示元に返す情報(メソッドの戻り値)
4. 処理内容

例：操作が「眠る」の場合

名前：sleep
必要情報：なし
結果：なし
処理内容：HPが100に回復する

上記の情報をHeroクラスのクラスブロック内に追加する形で記述する。
```
public class Hero {
    String name;
    int hp;
    
    public void sleep(){
        this.hp = 100;
        System.out.println(this.name + "は、眠って回復した！");
    }
}
```
ここで使われているthisとは「自身のインスタンス」を意味する。
なので
```
this.hp = 100;
```
とは、自身のインスタンスのhpフィールドに100を代入するという意味になる。

#### 5-6. クラス名とメンバ名のルール

上記のフィールドとメソッドはメンバと総称される。  
基本的には以下のルールに則って命名するのが望ましい。

| 対象   | 品詞 | 大文字/小文字の用法 | 例                      |
|------|------|------------------|------------------------|
| クラス名 | 名詞 | 単語の頭が大文字 | Hero、MonsterInfoなど     |
| フィールド名 | 名詞 | 最初以外の単語の頭が大文字 | name、itemListなど        |
| メソッド名 | 動詞 | 最初以外の単語の頭が大文字 | attack、findWeakPointなど |

#### 5-7. クラス定義のまとめ

ここまでHeroクラスを題材にクラスの定義方法を学んだ。  

クラスを定義する手順は以下の通り

1. 属性と操作をクラス図にまとめる。
2. 属性をフィールドとして、操作をメソッドとしてJavaのコードに書き換える。

これまで記述してきたフィールドとメソッドに「座る」「転ぶ」「逃げる」を追加したものが以下の通りになる。

chapter08/code08-01/src/Hero.java
```
public class Hero {
    String name;
    int hp;

    public void sleep(){
        this.hp = 100;
        System.out.println(this.name + "は、眠って回復した！");
    };

    public void sit(int sec){
        this.hp += sec;
        System.out.println(this.name + "は、" + sec + "秒座った！");
        System.out.println("HPが" + sec + "ポイント回復した");
    };

    public void slip(){
        this.hp -= 5;
        System.out.println(this.name + "は、転んだ！");
        System.out.println("5のダメージ！");
    };

    public void run(){
        System.out.println(this.name + "は、逃げ出した！");
        System.out.println("GAMEOVER");
        System.out.println("最終HPは、" + this.hp + "でした");
    };
}
```

注意点としては、thisを省略しないこと。  

同じクラス内のフィールドにアクセスする場合は`this.`を省略しても動作はする。  
`this.hp = 100;`と`hp = 100;`は同じ動作ではあるが、  
ローカル変数や引数にも同じhpという変数があるとそちらが優先されてしまうなど、  
予想外の動きをすることになってバグの原因にも繋がる。  
そのため、フィールドを指示する時は必ず`this.`を記述する。

### 6. クラス定義による効果

クラス定義により、以下の2つのことが可能になる。

1. 定義したクラスに基づいてインスタンスを生成できるようになる。
2. 定義したクラスから生成したインスタンスを代入する変数の型が使用可能になる。

Javaで変数を扱うには、必ず型が必要になる。  
これまではint型やString型、int[]型など、  
あらかじめJavaが用意してくれた型を使用していたが、  
クラス定義により、追加でその定義したクラスの型を使用できるようになる。  
今回Heroクラスを定義したとしたら、Hero型が追加で使えるようになる。  
こうすることで、Javaで使用できる型はどんどん増えていくことになる。

クラス型変数の宣言方法は以下の通り  
（ここではHero型とする）
```
Hero h;
```

この状態ではまだインスタンスは入っていないが、  
インスタンスは通常、このクラス型変数に入れて利用する。

### 7. クラス型変数が必要な理由

なぜHero型(クラス型)変数にインスタンスを代入する必要があるのか？

仮想世界に存在しうる同名のインスタンスの中から、  
特定の1つのインスタンスをプログラムとして識別するため。  

仮に定義したHeroクラスから同じ中身のインスタンスを生成したとする。  
両方とも名前は「ミナト」で、HPは「100」であるとする。  
ではこの状態で両方のインスタンスは仮想世界でどうやって識別するのか？

紙にでも書けば、「左のミナト」「右のミナト」とか識別は可能であるが、  
仮想世界においてはこの両者を識別する方法はない。  
そのため、`Hero h1;`や`Hero h2;`など、  
クラス型変数を用意して、インスタンスをクラス型変数に代入する必要がある。  
すると、h2のインスタンスに「眠れ」と指示すれば、  
h2の勇者だけが眠る動作をすることになる。

### 8. インスタンスの利用方法

#### 8-1. 神様クラスの作り方

Heroクラスは先ほど作成したが、このクラスだけでは動作しない。  
Heroクラスのインスタンスを生成するために、  
「神様クラス」であるMainクラスを作成する。  

```
public class Main {
    public static void main(String[] args) {
        // ここに勇者への指示を書いていく
    }
}
```

mainメソッドに以下を記述する。

1. 仮想世界に勇者を生み出す。
2. 生み出された勇者の名前とHPを設定する
3. 勇者に「5秒座れ」「転べ」「25秒座れ」「逃げろ」と指示を出す。

#### 8-2. インスタンスの生成方法

以下のように記述することで、  
定義したクラスからインスタンスを生成できる。
```
クラス名 変数名 = new クラス名();
```
では実際に仮想世界に勇者を生み出す部分をJavaのコードにしてみる。
```
public class Main {
    public static void main(String[] args) {
        Hero h = new Hero();  // Heroクラスからインスタンスを生成し、変数hへ代入
    }
}
```
`new Hero()`の部分でインスタンスを生成している。  
生成されたインスタンスを=を使ってHero型のクラス変数hへ代入している。

#### 8-3. インスタンスのフィールド利用

生成したばかりの状態の勇者hには、まだ名前もなければHPもない。  
そのため、それぞれのフィールドに以下の方法で値を代入する必要がある。

```
変数名.フィールド名 = 値;
```

以上の方法で、mainメソッドに追記してみる。

```
public class Main {
    public static void main(String[] args) {
        Hero h = new Hero();
        h.name = "ミナト";
        h.hp = 100;
        System.out.println("勇者" + h.name + "を生み出しました！");
    }
}
```

#### 8-4. インスタンスのメソッド呼び出し

さまざまな指示を勇者に送ってみる。

```
public class Main {
    public static void main(String[] args) {
        Hero h = new Hero();
        h.name = "ミナト";
        h.hp = 100;
        System.out.println("勇者" + h.name + "を生み出しました！");

        h.sit(5);   // 5秒座れ
        h.slip();   // 転べ 
        h.sit(25);  // 25秒座れ
        h.run();    // 逃げろ
    }
}
```

### 9. オブジェクト指向のクラスは現実世界と繋がっている

chapter06までで書いたコードとchapter08で書いたコードを比較してみる。  
同じ`public class クラス名`で宣言されたクラスであるが、  
どちらとも文法的には正しい。  

では何が違うのか？

この両者には「クラスを何のために用いるか」という思想が伴っているか否かの違いがある。

前者の場合は、  
「そろそろメソッドが大きくなったので分割しよう」、  
あるいは「この機能はこのクラスにまとめておこう」という、  
開発者の都合や機能の単位に即してクラスやメソッドを作成していた。

一方、Heroクラスなど、後者の場合は、  
「オブジェクト指向」という明確な思想に基づいてクラスやメソッドが作られている。  
つまり、現実世界の登場人物を1つのクラスと捉え、  
その登場人物の持つ属性をフィールドに、
操作をメソッドとしてコードを書いた。  

chapter06までは「現実世界とは無関係なクラス」を書いてきたが、  
chapter08で初めて「現実世界と意味が繋がったクラス」に出会ったことになる。  
いくつものクラスやメソッドを作っても、  
chapter06までとchapter08では印象が違うと感じるのはこのためである。

以上から、オブジェクト指向を意識したプログラム開発とは、  
現実世界の人や物、出来事などをクラスに置き換える作業とも言える。

現実世界に似せて作り、  
現実世界に似せて動かす。  
これがオブジェクト指向の根本的な思想である。
