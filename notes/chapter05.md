## 用語集 & 補足

### 1. 用語

- メソッド：複数の文をまとめ、一つの処理として名前をつけた部品の最小単位。
- 引数：メソッドを呼び出す際に、呼び出し元から渡される値のこと。
- 実引数：メソッドに渡す値のこと。
- 仮引数：メソッドが受け取る変数のこと。
- ローカル変数：メソッド内で宣言した変数のこと。仮引数もその一種。
- 戻り値：呼び出されたメソッドから呼び出し元のメソッドへ戻される値。返り値ともいう。
- オーバーロード：同じ名前のメソッドを定義すること。
- シグネチャ：メソッド宣言に記述するメソッド名・引数の個数・引数の型・引数の並び順の総称。
- 値渡し：メソッドに値そのものが渡される呼び出し方。
- 参照渡し：メソッドの引数としてアドレスを渡す呼び出し方。
- コマンドライン引数：Javaプログラム起動時に指定できる追加情報のこと。

### 2. メソッドとは

#### 2-1. メソッドを利用するメリット

これまでは全てmainメソッドの中に全ての文を並べてプログラムを作成してきた。  
登場したコードは長くて30行程度で済んでいたが、  
もしmainメソッドだけで巨大なプログラムを作るとどうなるだろうか？

たとえば開発中に「表示内容を修正してほしい」と頼まれて、  
ソースコードの修正が必要になった場合、  
修正箇所を探すだけでも大変な作業になってしまう。

Javaをはじめとする多くのプログラミング言語では、  
このような不便がないように1つのプログラムを複数の部品に分けて開発できる部品化の仕組みが備わっている。  
メソッドは、複数の文をまとめて1つの処理として名前をつけたもので、部品の最小単位である。

例えばmainメソッド内の処理を複数に分割して処理を担当させることができる。  
mainメソッドは分割した処理を呼び出すだけなので、コードがすっきりとし、見通しがよくなる。  
つまり、機能単位でメソッドを分割すれば、全体把握が楽になる。

まとめると、メソッド利用のメリットは
1. プログラムの見通しが良くなり、全体を把握しやすくなる。
2. 機能単位に記述するため、修正範囲を限定できる。
3. 同じ処理を1つにまとめることで、作業効率が上がる。

#### 2-2. メソッドの定義

メソッドを使用するには2ステップがある

1. メソッドを作成する
2. 作成したメソッドを使用する

シンプルなメソッドの定義
```
public static void メソッド名(){
    // メソッドが呼び出されたときの処理
}
```
シンプルなメソッド定義のサンプルコードは後述する。

#### 2-3. メソッドの呼び出し

2-2で定義したメソッドを使用するには以下のようにメソッドを呼び出す必要がある。
```
メソッド名()
```

シンプルなメソッドの定義と呼び出し
(chapter05/code05-01/src/Main.java)
```
public class Main {
    public static void main(String[] args) {
        System.out.println("メソッドを呼び出します");
        hello();
        System.out.println("メソッド呼び出しが終了しました。");
    }

    public static void hello(){
        System.out.println("hello world");
    }
}
```

このプログラムの8行目から10行目でメソッドを定義し、  
4行目でメソッドを呼び出している。

8行目のhelloは、定義するメソッドの名前（メソッド名）である。  
そして8行目から10行目の{}内（今回は9行目）をメソッドブロックという。  
ここがhelloメソッドを呼び出したときに実行される具体的な処理になる。  
今回はhello worldを出力しているが、必要に応じて複数行記述する。

なお、定義しただけでは、mainメソッドから呼び出されていないため実行はできない。  
そのために、4行目でmainメソッドからhelloメソッドの呼び出しが必要になる。

2行目でmainメソッドが、そして8行目でhelloメソッドが定義されている。  
このプログラムを実行すると、まず2行目にあるmainメソッドが自動的に開始される。
そして4行目のhello();でhelloメソッドを呼び出す。

これを実行すると、結果は以下のようになる。
```
メソッドを呼び出します
hello world
メソッド呼び出しが終了しました。
```

このように、メソッドは定義しただけでは実行されず、  
呼び出されて初めてメソッドに定義した処理が実行される。

例えば、4行目のhello();を削除すると、  
「hello world」は表示されなくなる。  
また、呼び出されたメソッドが終了すると、  
呼び出し元に戻ってきて処理の続きが実行される。

#### 2-4. mainメソッド以外からのメソッド呼び出し

メソッドはmainメソッド以外からも呼び出すことができる。  

chapter05/code05-02/src/Main.java
```
public class Main {
    public static void methodA(){
        System.out.println("methodA");
        methodB();
    }

    public static void methodB(){
        System.out.println("methodB");
    }

    public static void main(String[] args) {
        methodA();
    }
}
```

このプログラムでは、methodA()がmethodB()を呼び出している。  
処理の流れとしては、main()→methodA()→methodB()の順番に実行される。

このプログラムの実行結果は以下のとおり
```
methodA
methodB
```

なお、ソースコード中に複数のメソッドが定義されている場合、  
その順序に特に意味や制約はない。  
mainメソッドの上にあろうが下にあろうが、  
プログラムを実行したときに一番最初に動くのははmainメソッドである。  
各メソッドが動く順序は、mainメソッドを起点にどう呼び出されるかで決まる。

#### 2-5. メソッドにまつわる2つの立場

1. メソッドを定義する立場
2. メソッドを呼び出す立場

chapter05/code05-01/src/Main.javaの再掲
```
public class Main {
    public static void main(String[] args) {
        System.out.println("メソッドを呼び出します");
        hello();
        System.out.println("メソッド呼び出しが終了しました。");
    }

    public static void hello(){
        System.out.println("hello world");
    }
}
```

このメソッドでmain()とhello()の2つのメソッドを自分で作成した。  
しかし、「helloメソッドを定義する自分」と「mainメソッドの中でhelloメソッドを呼び出す自分」を  
あたかも別の人物として捉えてプログラムを書くことがJavaプログラミング上達の近道である。

本格的な業務システムを開発する大規模プロジェクトの場合、  
何百人もの開発者が手分けして作業するため、  
メソッドを定義する人とメソッドを呼び出す人は、  
まったくの別人になることが多い。

メソッドを定義する人は、メソッドを呼び出す人のことを考えてメソッドを作成すべきである。  
例えばaaa()やkeisan()のような名前のメソッド名をつけるべきではない。  
なぜなら、メソッドの内容を想像しにくくなるばかりでなく、  
そのメソッドを呼び出す側のプログラムも、  
何の処理をしているのか読み取れなくなってしまうためである。  
処理内容のわかりにくさは、メソッドからそれを利用する側の処理へと波及し、  
プログラム全体へと拡大してしまう。

良い例：  
hello(); → 挨拶を表示していると推測できる  
saveToFile(); → ファイルに保存していることが推測できる

悪い例:  
aaa(); → 何をしているのか推測できない

aaaの内容が推測できないため、  
このmainメソッドもどんな動きをするメソッドなのか想像がつかない。

メソッド名は、メソッドを定義する人だけでなく、  
メソッドを呼び出す人にも大きな影響を与える。  
自分一人だけでなく、同じチームメンバーの開発効率にも大きく影響を及ぼすため、  
メソッド名を適切につけることは非常に重要である。

helloメソッドのようなシンプルなメソッドでも、複雑なメソッドの場合でも、  
メソッド定義は必ず2つの部分から構成されている。

```
public static void hello(){             // ①重要事項の表明
    System.out.println("hello world");  // ②処理内容
}
```

メソッド定義の1行目はメソッドを定義する人とメソッドを呼び出す人の双方に関わる重要な情報が記述されるため特に重要な部分である。  
メソッドを定義する側は、「この名前でこのように呼び出してほしい」と表明する。  
メソッドを呼び出す側は、1行目に記述された情報を見て、「この名前でこの形式で呼び出せばよい」と理解する。  

以上をまとめると、メソッド定義の1行には、  
定義する人と呼び出す人の接点となる重要な情報が書かれる。

メソッド定義の2行目以降のメソッドブロックは、1行目ほど重要度は高くない。  
この部分の詳細を気にしなければならないのは、メソッドを定義する人だけのため。  
メソッドを呼び出す人は、「正しい形式で呼び出しさえすればきちんと仕事をしてくれる」という前提のもとにメソッドを呼び出している。  
呼び出す側はいちいちメソッドが内部でどのように処理しているかまではいちいち気にする必要がない。
