## 用語集 & 補足

### 1. 用語

- メソッド：複数の文をまとめ、一つの処理として名前をつけた部品の最小単位。
- 引数：メソッドを呼び出す際に、呼び出し元から渡される値のこと。
- 実引数：メソッドに渡す値のこと。
- 仮引数：メソッドが受け取る変数のこと。
- ローカル変数：メソッド内で宣言した変数のこと。仮引数もその一種。
- 戻り値：呼び出されたメソッドから呼び出し元のメソッドへ戻される値。返り値ともいう。
- オーバーロード：同じ名前のメソッドを定義すること。
- シグネチャ：メソッド宣言に記述するメソッド名・引数の個数・引数の型・引数の並び順の総称。
- 値渡し：メソッドに値そのものが渡される呼び出し方。
- 参照渡し：メソッドの引数としてアドレスを渡す呼び出し方。
- コマンドライン引数：Javaプログラム起動時に指定できる追加情報のこと。

### 2. メソッドとは

#### 2-1. メソッドを利用するメリット

これまでは全てmainメソッドの中に全ての文を並べてプログラムを作成してきた。  
登場したコードは長くて30行程度で済んでいたが、  
もしmainメソッドだけで巨大なプログラムを作るとどうなるだろうか？

たとえば開発中に「表示内容を修正してほしい」と頼まれて、  
ソースコードの修正が必要になった場合、  
修正箇所を探すだけでも大変な作業になってしまう。

Javaをはじめとする多くのプログラミング言語では、  
このような不便がないように1つのプログラムを複数の部品に分けて開発できる部品化の仕組みが備わっている。  
メソッドは、複数の文をまとめて1つの処理として名前をつけたもので、部品の最小単位である。

例えばmainメソッド内の処理を複数に分割して処理を担当させることができる。  
mainメソッドは分割した処理を呼び出すだけなので、コードがすっきりとし、見通しがよくなる。  
つまり、機能単位でメソッドを分割すれば、全体把握が楽になる。

まとめると、メソッド利用のメリットは
1. プログラムの見通しが良くなり、全体を把握しやすくなる。
2. 機能単位に記述するため、修正範囲を限定できる。
3. 同じ処理を1つにまとめることで、作業効率が上がる。

#### 2-2. メソッドの定義

メソッドを使用するには2ステップがある

1. メソッドを作成する
2. 作成したメソッドを使用する

シンプルなメソッドの定義
```
public static void メソッド名(){
    // メソッドが呼び出されたときの処理
}
```
シンプルなメソッド定義のサンプルコードは後述する。

#### 2-3. メソッドの呼び出し

2-2で定義したメソッドを使用するには以下のようにメソッドを呼び出す必要がある。
```
メソッド名()
```

シンプルなメソッドの定義と呼び出し
(chapter05/code05-01/src/Main.java)
```
public class Main {
    public static void main(String[] args) {
        System.out.println("メソッドを呼び出します");
        hello();
        System.out.println("メソッド呼び出しが終了しました。");
    }

    public static void hello(){
        System.out.println("hello world");
    }
}
```

このプログラムの8行目から10行目でメソッドを定義し、  
4行目でメソッドを呼び出している。

8行目のhelloは、定義するメソッドの名前（メソッド名）である。  
そして8行目から10行目の{}内（今回は9行目）をメソッドブロックという。  
ここがhelloメソッドを呼び出したときに実行される具体的な処理になる。  
今回はhello worldを出力しているが、必要に応じて複数行記述する。

なお、定義しただけでは、mainメソッドから呼び出されていないため実行はできない。  
そのために、4行目でmainメソッドからhelloメソッドの呼び出しが必要になる。

2行目でmainメソッドが、そして8行目でhelloメソッドが定義されている。  
このプログラムを実行すると、まず2行目にあるmainメソッドが自動的に開始される。
そして4行目のhello();でhelloメソッドを呼び出す。

これを実行すると、結果は以下のようになる。
```
メソッドを呼び出します
hello world
メソッド呼び出しが終了しました。
```

このように、メソッドは定義しただけでは実行されず、  
呼び出されて初めてメソッドに定義した処理が実行される。

例えば、4行目のhello();を削除すると、  
「hello world」は表示されなくなる。  
また、呼び出されたメソッドが終了すると、  
呼び出し元に戻ってきて処理の続きが実行される。

#### 2-4. mainメソッド以外からのメソッド呼び出し

メソッドはmainメソッド以外からも呼び出すことができる。  

chapter05/code05-02/src/Main.java
```
public class Main {
    public static void methodA(){
        System.out.println("methodA");
        methodB();
    }

    public static void methodB(){
        System.out.println("methodB");
    }

    public static void main(String[] args) {
        methodA();
    }
}
```

このプログラムでは、methodA()がmethodB()を呼び出している。  
処理の流れとしては、main()→methodA()→methodB()の順番に実行される。

このプログラムの実行結果は以下のとおり
```
methodA
methodB
```

なお、ソースコード中に複数のメソッドが定義されている場合、  
その順序に特に意味や制約はない。  
mainメソッドの上にあろうが下にあろうが、  
プログラムを実行したときに一番最初に動くのははmainメソッドである。  
各メソッドが動く順序は、mainメソッドを起点にどう呼び出されるかで決まる。

#### 2-5. メソッドにまつわる2つの立場

1. メソッドを定義する立場
2. メソッドを呼び出す立場

chapter05/code05-01/src/Main.javaの再掲
```
public class Main {
    public static void main(String[] args) {
        System.out.println("メソッドを呼び出します");
        hello();
        System.out.println("メソッド呼び出しが終了しました。");
    }

    public static void hello(){
        System.out.println("hello world");
    }
}
```

このメソッドでmain()とhello()の2つのメソッドを自分で作成した。  
しかし、「helloメソッドを定義する自分」と「mainメソッドの中でhelloメソッドを呼び出す自分」を  
あたかも別の人物として捉えてプログラムを書くことがJavaプログラミング上達の近道である。

本格的な業務システムを開発する大規模プロジェクトの場合、  
何百人もの開発者が手分けして作業するため、  
メソッドを定義する人とメソッドを呼び出す人は、  
まったくの別人になることが多い。

メソッドを定義する人は、メソッドを呼び出す人のことを考えてメソッドを作成すべきである。  
例えばaaa()やkeisan()のような名前のメソッド名をつけるべきではない。  
なぜなら、メソッドの内容を想像しにくくなるばかりでなく、  
そのメソッドを呼び出す側のプログラムも、  
何の処理をしているのか読み取れなくなってしまうためである。  
処理内容のわかりにくさは、メソッドからそれを利用する側の処理へと波及し、  
プログラム全体へと拡大してしまう。

良い例：  
hello(); → 挨拶を表示していると推測できる  
saveToFile(); → ファイルに保存していることが推測できる

悪い例:  
aaa(); → 何をしているのか推測できない

aaaの内容が推測できないため、  
このmainメソッドもどんな動きをするメソッドなのか想像がつかない。

メソッド名は、メソッドを定義する人だけでなく、  
メソッドを呼び出す人にも大きな影響を与える。  
自分一人だけでなく、同じチームメンバーの開発効率にも大きく影響を及ぼすため、  
メソッド名を適切につけることは非常に重要である。

helloメソッドのようなシンプルなメソッドでも、複雑なメソッドの場合でも、  
メソッド定義は必ず2つの部分から構成されている。

```
public static void hello(){             // ①重要事項の表明
    System.out.println("hello world");  // ②処理内容
}
```

メソッド定義の1行目はメソッドを定義する人とメソッドを呼び出す人の双方に関わる重要な情報が記述されるため特に重要な部分である。  
メソッドを定義する側は、「この名前でこのように呼び出してほしい」と表明する。  
メソッドを呼び出す側は、1行目に記述された情報を見て、「この名前でこの形式で呼び出せばよい」と理解する。  

以上をまとめると、メソッド定義の1行には、  
定義する人と呼び出す人の接点となる重要な情報が書かれる。

メソッド定義の2行目以降のメソッドブロックは、1行目ほど重要度は高くない。  
この部分の詳細を気にしなければならないのは、メソッドを定義する人だけのため。  
メソッドを呼び出す人は、「正しい形式で呼び出しさえすればきちんと仕事をしてくれる」という前提のもとにメソッドを呼び出している。  
呼び出す側はいちいちメソッドが内部でどのように処理しているかまではいちいち気にする必要がない。

### 3. 引数の利用

#### 3-1. 引数とは

メソッドを呼び出す際に、呼び出し元から値を渡すことができる。  
このときに渡される値を引数と呼ぶ。  
呼び出されたメソッド側では、渡された値を受け取って処理に利用できる。  
引数には数値や文字列などを指定でき、その値や型、渡す引数の数は開発者が自由に決めることができる。  

#### 3-2. 1つの引数を渡す

サンプルプログラム
(chapter05/code05-03/src/Main.java)
```
public class Main {
    public static void main(String[] args) {
        System.out.println("メソッドを呼び出します");
        hello("Hiroya");
        hello("Nagano");
        System.out.println("メソッドの呼び出しが終わりました");
    }
    public static void hello(String name){
        System.out.println("Hello " + name);
    }
}
```
実行結果は以下のとおり
```
メソッドを呼び出します
Hello Hiroya
Hello Nagano
メソッドの呼び出しが終わりました
```

まずは4行目のhello("Hiroya");の部分で、()の中に「Hiroya」という文字列の値が入っている。  
このように、メソッドを呼び出す際、()の中に値を入れておくと、  
その値が引数として呼び出される側のhelloメソッドに渡される。  
(同様に、5行目の「Nagano」も引数としてhelloメソッドに渡される。)

8行目では、メソッド名の後ろにある()の中で、  
「String name」として文字列変数nameを宣言している。  
helloメソッドが呼び出されると、  
変数nameに呼び出し元から引数として渡された「Hiroya」が自動的に代入され、  
メソッドブロック内で使用可能になる。
この例では、画面出力に使用されており、  
「Hello Hiroya」を表示している。

#### 3-3. 複数の引数を渡す

サンプルコード
(chapter05/code05-04/src/Main.java)
```
public class Main {
    public static void main(String[] args) {
        add(100, 20);
        add(200, 50);
    }
    public static void add(int x, int y){
        int ans = x + y;
        System.out.println(x + "+" + y + "=" + ans);
    }
}
```

引数として渡す値が複数ある場合は、値をカンマで区切って使用する。  
また、値を受け取るメソッド側でも、受け取る変数をカンマで区切って宣言する。  
このとき、引数として渡される値と、メソッド側で宣言する変数の型と順番を合わせておく必要がある。

コンパイルエラーになる例
```
public class Main {
    public static void main(String[] args) {
        add(100, "abc");
    }
    public static void add(int x, int y){
        int ans = x + y;
        System.out.println(x + "+" + y + "=" + ans);
    }
}
```

3行目にaddで(100, "abc")としているが、  
5行目のメソッド定義では両方ともint型であるので、  
文字列型の値を整数型の変数で受け取ることができず、コンパイルエラーになる。

このように、引数と変数の型が合致しない場合は、
コンパイルエラーが発生する。

以上をまとめると、

引数を利用したメソッド定義
```
public static void メソッド名(引数リスト){
}
```

引数を利用したメソッド呼び出し
```
メソッド名(引数リスト)
```
値には変数名も使用できる。  
また、複数の引数を渡すときはカンマで区切って指定する。

#### 3-4. 仮引数と実引数

値を渡すのも受けるのも、()ないの引数リストで行う。  
メソッドに渡す値、メソッドが受け取る変数の両方が「引数」と呼ばれるが、  
厳密に区別する場合、メソッドに渡す値を実引数、  
メソッドが受け取る変数を仮引数という。

実引数の例
```
add(100, 20);
```
この100と20が実引数となる。

仮引数の例(addメソッド内)
```
int ans = x + y;
```
このxとyが仮引数となる。

#### 3-5. 変数のスコープとローカル変数

以下の場合はコンパイルエラーになる
```
public class Main {
    public static void main(String[] args) {
        int x = 100;
        int y = 10; 
        add();
    }
    public static void add(){
        int ans = x + y;
        System.out.println(x + "+" + y + "=" + ans);
    }
}
```

変数のスコープとは、その変数が利用できる有効範囲である。  
ブロック内で宣言された変数のスコープは、そのブロック内に限定される。  
このような変数の性質をローカル変数の独立性という。  
そのため、mainメソッド内で宣言したxとyは、  
mainメソッドブロックの中でしか使えない。

```
public class Main {
    public static void main(String[] args) {
        int x = 100;  // ①
        for(int i = 0;・・・){
          int y = 200;  // ②
          ・・・
        }
        methodA(x);
    }
    
    public static void methodA(int x){  // ③
        int y = 10; // ④
        ・・・
    }
}
```

それぞれの変数の有効範囲

①変数宣言してからmainメソッドの最後まで
②変数宣言してからfor文の最後まで
③methodAメソッドの{}内のみ
④変数宣言してからmethodAメソッドの最後まで

main()やadd()といったメソッド内で宣言した変数をローカル変数という。  
仮引数も、このローカル変数の一種である。  

ローカル変数は、その変数が属するメソッド内のみ有効である。  
別のメソッドに属する同名のローカル変数とはまったくの別物である。  

上記の場合、「mainメソッド内の変数y」と「methodA内の変数y」の2つは、  
同一の変数名であっても無関係の存在である。
methodAの変数yにどんな値を代入しても、  
mainメソッドの変数yには一切影響はない。

簡単にまとめると、ローカル変数の独立性とは、  
異なるメソッドに属するローカル変数は、  
お互いに独立していて無関係であるということである。

### 4. 戻り値の利用

#### 4-1. 戻り値とは

呼び出されたメソッドから呼び出し元のメソッドへ値を返すことを値を戻す、または値を返すという。  
また、このとき戻される値のことを戻り値という。

戻り値のメソッド定義は以下のとおり
```
public static 戻り値の型 メソッド名(引数リスト){
  //　メソッドの処理
  return 戻り値;
}
```

メソッドブロックの最終行にreturn文がある。  
これはreturnの後ろに書かれた値を呼び出し元に戻す役割がある。  
変数に入っている値を戻すには、`return 変数名;`のように変数名を指定する。   
`return 100;`や`return hello;`のようにリテラルを指定することも可能。  

次に、メソッド名の左側はvoidではなく、戻り値の型になっている。  
ここにはreturnによって戻される値と同じ型を指定する。  

例：
100を戻す → int
"hello"を戻す → String
変数に入っている値 → その変数の型
何も戻さない → void

#### 4-2. 戻り値を受け取る

戻り値を受け取る側は以下の形で受け取ることができる。
```
型 変数名 = メソッド名（引数リスト）;
```

文に代入演算子「=」がある場合は、常に右側から評価されるので、  
まずはメソッド呼び出しが実行される。  
呼び出されたメソッドがreturn文によって値を戻す場合、
「メソッド名(引数リスト)」の部分は評価されて戻ってきた値に置き換わる。  
これにより、`型 変数名 = メソッドの戻り値;`という状態になり、  
戻り値が変数に代入される。

戻り値を使ったサンプルコード
(chapter05/code05-05/src/Main.java)
```
public class Main {
    public static int add(int x,int y){
        int ans = x + y;
        return ans;
    }

    public static void main(String[] args) {
        int ans = add(100, 10);
        System.out.println("100 + 10 = " + ans);
    }
}
```

初心者のよくある間違い

①add(100, 10) = int ans;
②add(100, 10)

①は構文として間違っているのでコンパイルエラーになる。  
②は`int ans = `が抜けている。  
mainメソッドで結果の110は戻っているが呼び出し元で受け取っていないため、  
mainメソッドで受け取っていない。

#### 4-3. 戻り値をそのまま使う

メソッドの戻り値を変数で受けずにそのまま使用することもできる。  

戻り値をそのまま使うサンプルコード
```
public class Main {
    public static int add(int x,int y){
        int ans = x + y;
        return ans;
    }

    public static void main(String[] args) {
        System.out.println(add(add(10, 20), add(30, 40)));
    }
}
```

実行結果
```
100
```

流れとしては  
①add(10, 20)が実行され、30が戻ってくる。  
②add(30, 40)が実行され、70が戻ってくる。  
この時点でadd(10, 20)は30に化け、add(30, 40)は70に化ける。  
③この結果、add(30, 70)が実行され、100が戻ってくる。  
④100が画面に出力される。

#### 4-4. return文の注意点

return文は値を戻すだけでなく、メソッドの終了も行う。  
そのため、return文の後に処理を書いても実行されない。  
そのようなメソッドを記述するとコンパイルエラーになってしまう。
